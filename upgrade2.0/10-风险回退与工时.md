# 风险、回退策略与工时估算

## 一、关键风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| phase_plan LLM 调用增加延迟 | 用户感知对话变慢 0.5-1s | skip_plan 参数允许前端跳过；简单问题自动 steps=[]；模板命中走 0 Token 路径 |
| 原子工具数量增多导致 Function Calling 选择困难 | LLM 选错工具 | 工具 description 精确描述差异；plan 阶段预先指导工具选择；组合工具承担"打包调用" |
| 工作流执行失败率高于预期 | 用户不信任定时任务 | P7 Admin Monitor 实时监控；失败时 notifier 推送告警 |
| 组合工具与 Pipeline 旧路径输出不一致 | 用户看到的数据变化 | P6 环境变量开关可随时回退；P8 回归测试覆盖 |
| 模板匹配累积的 auto_template 数据膨胀 | DB 增长过快 | 定期清理（hit_count < 3 且超过 30 天的 auto_template 可清理） |
| ContextVar 跨线程漏设导致 with_owner 报错 | scheduler 路径全面失败 | P6 set_current_owner + reset_current_owner 强制配对 |
| workflow_id 作为 Prometheus label | 时序爆炸（每千工作流千条 histogram） | R-016：去掉 workflow_id label，histogram 只看整体分布 |
| 用户越权取消他人工作流 | 安全漏洞 | R-012：cancel API 必走 owner 校验 |

## 二、回退策略

| 组件 | 回退方式 | 回退影响 |
|------|---------|---------|
| 组合工具 → Pipeline 旧路径 | `USE_COMPOSITE_TOOLS=0` 环境变量 | 调度器走旧路径，Agent 工具调用不受影响 |
| phase_plan | 前端传 `skip_plan=true`；或 LLM 故障时自动回退 steps=[] | 退化为当前无计划模式，功能无损 |
| 工作流执行 | `UPDATE workflows SET enabled=0 WHERE source='user'` | 定时任务停止，手动对话不受影响 |
| Admin Monitor 新端点 | 新端点为增量，旧端点不改 | 前端不调用新端点则无感知 |
| 新增 Prometheus 指标 | 删 metrics.py 末尾代码 | 已记录的指标数据失效，不影响历史 |
| snapshot 表新增字段 | 字段是 NULL-default，不影响旧查询 | 新查询需要 NULL 处理 |
| 新增 I 组组合工具 | 删 `from . import composite` 一行 | preset 工具从 _REGISTRY 消失，Agent 无法调用 |

### 紧急回退步骤（30 秒内完成）

```bash
# 1. 关闭调度器新路径
export USE_COMPOSITE_TOOLS=0
# 2. 重启 gateway
systemctl restart mediaradar-gateway
# 3. 禁用所有定时工作流
sqlite3 data/mediaradar.db "UPDATE workflows SET enabled=0 WHERE source='user';"
# 4. 观察 5 分钟
tail -f logs/gateway/*.log
```
