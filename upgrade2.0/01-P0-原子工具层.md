# P0 — 原子工具层（含 Pipeline 升级算法移植）

> 依赖：无
> 目标：将管线五阶段拆解为 12 个可独立调用的原子工具，同时将 pipeline升级.md 中的算法移植到对应工具实现中
> 原则：每个工具做一件事，参数和返回值都是标准 JSON，沿用 @tool() 装饰器

## 一、工具清单

### 1.1 采集类

| 工具名 | 功能 | 参数 | 返回值 |
|--------|------|------|--------|
| `search_posts` | 按关键词+平台搜索帖子 | keyword*, platforms[], limit | JSON: [{title, content, platform, url, time}] |

**实现要点：**
- 内部调用 CrawlerManager 按需采集
- 如果 CrawlerManager 不在运行中，启动它
- 如果对应平台熔断中（CircuitBreaker OPEN），返回错误信息含预计恢复时间
- 搜索结果不做过滤，返回原始列表

### 1.2 过滤类

| 工具名 | 功能 | 参数 | 返回值 |
|--------|------|------|--------|
| `filter_content` | 按意图过滤帖子 | posts*, intent (risk/guide/celebrity/briefing) | JSON: [{post + screener_result}] |

**实现要点：**
- 内部调用 ScreenerStage，根据 intent 选择对应的 Prompt：
  - `risk` → SCREENER_PROMPT（舆情）
  - `guide` → GUIDE_SCREENER_PROMPT（攻略）
  - `celebrity` → CELEBRITY_SCREENER_PROMPT（追星）
  - `briefing` → BRIEFING_SCREENER_PROMPT（简报，全收）
- 复用现有 `ScreenerStage` 类的并发控制（screener_concurrency=10）
- 返回过滤后的帖子 + 每条帖子的 `is_relevant` / `sentiment` / `needs_vision` 等 Screener 判定字段

### 2.2 规则情感判定（analyze_sentiment 工具内）

```python
def _rule_sentiment(text: str) -> str:
    """规则层情感判定，零 token 成本，覆盖约 80% 的追星内容"""
    from .sentiment_dict import SENTIMENT_DICT
    pos = sum(1 for w in SENTIMENT_DICT["positive"] if w in text)
    neg = sum(1 for w in SENTIMENT_DICT["negative"] if w in text)
    if pos > neg * 2:
        return "positive"
    if neg > pos * 2:
        return "negative"
    return "neutral"  # 含模糊内容，由 LLM 补充判定
```

### 2.3 时间序列速度计算（calc_velocity 工具内）

```python
def _calc_velocity(snapshots: list[dict]) -> list[dict]:
    """输入 [{ts, positive, negative, neutral, volume}, ...]，输出带 delta 的快照列表"""
    result = []
    prev = None
    for s in snapshots:
        delta = {"positive": 0.0, "negative": 0.0, "volume": 0}
        if prev:
            delta["positive"] = s["positive"] - prev["positive"]
            delta["negative"] = s["negative"] - prev["negative"]
            delta["volume"] = s["volume"] - prev["volume"]
        result.append({**s, "delta": delta})
        prev = s
    return result
```

### 2.4 平台加权评分（compare_opinions 工具内）

```python
PLATFORM_WEIGHTS = {
    "xhs": 0.3, "zhihu": 0.4, "bili": 0.3, "wb": 0.2,
}

def _calc_weighted_score(opinion: dict) -> float:
    """按平台类型加权计算综合评分"""
    total_weight = 0
    weighted_sum = 0
    for platform, count in opinion["platforms"].items():
        w = PLATFORM_WEIGHTS.get(platform, 0.25)
        total_weight += w * count
        weighted_sum += w * opinion.get("avg_rating", 3.0) * count
    return weighted_sum / total_weight if total_weight > 0 else 3.0
```

## 四、验收标准

- [ ] 12 个原子工具全部通过 `@tool()` 注册到 `_REGISTRY`
- [ ] 每个工具可被独立调用，参数校验正确（必填项缺失时返回明确错误）
- [ ] `search_posts` 在 CrawlerManager 未运行时返回明确错误信息（不抛未捕获异常）
- [ ] `filter_content` 四种 intent 切换正确，使用对应的 Screener Prompt
- [ ] `analyze_sentiment` 规则判定覆盖 80% 以上的追星内容（用 50 条样本验证）
- [ ] `calc_velocity` Delta 计算数值正确（用 3 个快照手工验证）
- [ ] `extract_slots` → `compare_opinions` → `generate_itinerary` 三个工具串联可输出完整 GuidePlanOutput
- [ ] 所有工具在异常路径下返回 JSON 含 `error` 字段，不抛未捕获异常
- [ ] `sentiment_dict.py` 可通过 `from .sentiment_dict import SENTIMENT_DICT` 导入
- [ ] 所有工具返回 JSON 通过 `ToolResult.to_json()` 包装（保证前端 ui.type 字段一致）
- [ ] 所有带数据库读写的工具走 `_owner_id` 上下文隔离（强制 `@with_owner` 装饰）

_INTENT_PROMPT_MAP = {
    "risk": (SCREENER_PROMPT, ScreenerResult),
    "guide": (GUIDE_SCREENER_PROMPT, GuideScreenerResult),
    "celebrity": (CELEBRITY_SCREENER_PROMPT, CelebrityScreenerResult),

    name="filter_content",
    description=(
        "按意图过滤帖子。intent: risk/guide/celebrity/briefing 决定使用哪个 Screener Prompt。"
        "常作为 search_posts 的下一步调用。"
    ),
    parameters={
        "type": "object",
        "properties": {
            "posts": {"type": "array", "description": "待过滤的帖子列表"},
            "intent": {"type": "string",

                       "description": "意图，决定使用哪个 Screener"},

        "required": ["posts", "intent"],
    },
    group="atomic",
)

def filter_content_tool(posts: list, intent: str, _owner_id: str) -> str:

        return ToolResult(success=False, error=f"未知 intent: {intent}",
                          error_type="validation").to_json()
    prompt, pyd = _INTENT_PROMPT_MAP[intent]
    stage = ScreenerStage(
        keywords=[], keyword_levels={},
        prompt=prompt, pydantic_model=pyd,
    )

    import asyncio
    loop = asyncio.get_event_loop()
    result = loop.run_until_complete(
        stage.run_batch(posts, owner_id=_owner_id)
    )
    return ToolResult(success=True, data=result,
                      ui={"type": "filtered_list", "data": result}).to_json()
