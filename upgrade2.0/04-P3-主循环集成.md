# P3 — 主循环进度注入 + 异常检测入口

> 依赖：P2（四维智能规划）
> 目标：在主循环中注入计划进度提示，每步执行后检测异常触发动态调整
> 原则：极简改动，不破坏现有主循环结构；criticality 由 P1 execute_workflow_steps 统一处理

## 一、进度注入实现（★ R-008 修订版：用临时变量，不污染 current_messages）

在 `chat_with_agent_stream` 主循环的 LLM 调用之前构造临时 messages：

```python
# agent_core.py — chat_with_agent_stream 主循环

for i in range(ctx.max_iterations):
    ctx.iteration = i

    # ── P3 新增: 进度注入（★ R-008 改：用临时变量，不入 current_messages）──
    plan = getattr(ctx, 'plan', None)
    plan_hint = None
    if plan and plan.get("steps"):
        step_idx = min(i + 1, len(plan["steps"]))
        step_desc = plan["steps"][min(i, len(plan["steps"])-1)].get("description", "")
        plan_hint = {
            "role": "system",
            "content": (
                f"【计划进度：第 {step_idx}/{len(plan['steps'])} 步】"
                f"当前步骤目标：{step_desc}"
                f" | 最终目标：{plan.get('goal', '')}"
            ),
        }

    # LLM 调用时构造临时 messages（不修改 ctx.current_messages）
    messages_for_llm = list(ctx.current_messages)
    if plan_hint:
        messages_for_llm.append(plan_hint)

    # ... 现有 LLM 调用 + 工具执行逻辑 ...
    # 注意：原代码中 `messages=ctx.current_messages` 改为 `messages=messages_for_llm`
    # ... （其他不变）...

    # ── P3 新增: 工具执行后异常检测（★ R-006 改：await 返回字符串）──
    if plan and plan.get("steps") and tool_was_called:
        step_result = _parse_last_tool_result(ctx.current_messages)
        adjusted_chunk = await _maybe_adjust_plan(step_result, step_idx - 1, ctx)
        if adjusted_chunk:
            yield adjusted_chunk  # emit_plan_adjusted → 通知前端
```

## 二、为何不在主循环实现 criticality（★ R-009 修订说明）

主循环路径走 LLM Function Calling（DirectAdapter），criticality 信息无法通过 OpenAI Function Calling 协议传递（LLM 不支持自定义字段）。

**criticality 三级行为仅在组合工具路径生效**，由 P1 的 `execute_workflow_steps` 实现：
- `critical` 失败 → 终止整个工作流
- `required` 失败 → 重试 2 次后降级
- `optional` 失败 → 静默跳过

主循环路径不重复实现，避免逻辑分叉。

## 三、取消检查点（保持原 P2 设计）

```python
# 主循环每轮开头检查取消
await cancel_registry.wait_or_raise(ctx.session_id, "iteration_start")
```

4 个检查点完整覆盖：
1. `phase_plan_start`（P2 模板匹配前）
2. `phase_plan_done`（P2 LLM 规划后）
3. `iteration_start`（P3 主循环每轮开头）
4. `_maybe_adjust_plan` 内的 LLM 调用（线程池可被中断）

## 四、auto_template 累积触发点

主循环结束后（用户中断或正常完成）调用：

```python
# chat_with_agent_stream 末尾
async for chunk in phase_finish(ctx):
    yield chunk

# ★ P2 新增：尝试保存 auto_template
if ctx.plan and ctx.plan.get("steps") and not ctx.user_intervened:
    await _maybe_save_template(ctx)
return
```

## 六、验收标准

- [ ] 当 ctx.plan 存在且 steps 非空时，每轮 LLM 调用的 messages 包含进度提示

- [ ] ctx.plan 不存在时，行为与 P2 之前完全一致
- [ ] 步骤返回空数据 → `_detect_anomaly` 返回非 None → 触发 `_maybe_adjust_plan` → emit_plan_adjusted 推前端
- [ ] `_maybe_adjust_plan` 返回字符串（不是 generator），主循环正确 yield
- [ ] 主循环路径不重复 criticality 处理
- [ ] auto_template 累积在 chat_with_agent_stream 末尾触发（正常完成或中断后）
- [ ] `ctx.user_intervened = True` 时跳过 auto_template 累积
- [ ] 4 个取消检查点全部生效（前端在任意检查点断开都能终止）
