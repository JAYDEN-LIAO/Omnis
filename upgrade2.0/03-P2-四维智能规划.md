# P2 — 四维智能规划模块（含取消检查点）

> 依赖：P0（原子工具层）
> 目标：在主循环前插入四维智能规划——约束提取 → 模板复用 → LLM 规划 → 动态调整
> 原则：plan 生成失败时回退到无计划模式，不阻断对话；四项能力互不冲突，可共存

## 三、phase_plan 函数（四维整合版，含 R-005/R-006 修订）

```python
# agent_core.py 新增

async def phase_plan(ctx: AgentContext):
    """
    四维智能规划：
    1. 模板匹配 → 命中直接返回（0 Token，放线程池执行）
    2. 未命中 → LLM 规划（含约束提取 + 关键路径标注）
    3. 执行后异常时 → 计划修正（不是 generator，普通 async 函数）
    """
    from backend.services.agent_service.workflows_db import WorkflowsDB
    from backend.core.metrics import AGENT_PLAN_GENERATION_TOTAL

    user_msg = _get_last_user_message(ctx)
    if not user_msg:
        return

    # ── 维度 2: 模板匹配（★ R-005 改：放线程池，可被 cancel） ──
    try:
        template = await _match_workflow_template(user_msg, ctx.owner_id)
        if template and template.get("hit_count", 0) >= 2:
            plan = _instantiate_template(template, user_msg)
            ctx.plan = plan
            ctx.adjustment_count = 0
            ctx.user_intervened = False
            AGENT_PLAN_GENERATION_TOTAL.labels(status="template_hit").inc()
            logger.info(f"[Plan] 模板命中: {template['name']} (hit_count={template['hit_count']})")
            yield emit_plan(plan)
            return
    except asyncio.CancelledError:
        raise
    except Exception as e:
        logger.warning(f"[Plan] 模板匹配异常（继续走 LLM）: {e}")

    # ── 维度 1+3: LLM 规划（约束提取 + 关键路径） ──
    plan_prompt = PLAN_PROMPT.format(
        user_message=user_msg,
        available_tools=_list_tool_names_for_planning(),
    )

    try:
        key, url, model = _get_agent_config_for(ctx.owner_id)
        client = OpenAI(api_key=key, base_url=url)
        # 同步调用放线程池 + 可被取消
        loop = asyncio.get_running_loop()
        content = await loop.run_in_executor(
            None,
            lambda: client.chat.completions.create(
                model=model or settings.DEFAULT_MODEL,
                messages=[{"role": "user", "content": plan_prompt}],
                temperature=0.2,
                max_tokens=400,
            ).choices[0].message.content.strip(),
        )
        plan = _parse_plan_json(content)
        AGENT_PLAN_GENERATION_TOTAL.labels(status="success").inc()
    except asyncio.CancelledError:
        raise
    except Exception as e:
        logger.warning(f"[Plan] LLM 规划失败，回退到无计划模式: {e}")
        plan = {
            "goal": "直接回答",
            "steps": [],
            "mode": "immediate",
            "constraints": {},
        }
        AGENT_PLAN_GENERATION_TOTAL.labels(status="fallback").inc()

    ctx.plan = plan
    ctx.adjustment_count = 0
    ctx.user_intervened = False
    logger.info(f"[Plan] LLM 出 plan: goal={plan.get('goal', '')}, steps={len(plan.get('steps', []))}")
    yield emit_plan(plan)


def _get_last_user_message(ctx: AgentContext) -> str:
    for m in reversed(ctx.messages):
        if m.get("role") == "user":
            return m.get("content", "")
    return ""


def _list_tool_names_for_planning() -> str:
    """返回工具清单（用于 PLAN_PROMPT 注入）。"""
    try:
        from backend.services.agent_service.tools import AVAILABLE_TOOLS
        return ", ".join(sorted(AVAILABLE_TOOLS.keys()))
    except Exception:
        return ""


def _parse_plan_json(content: str) -> dict:
    """解析 LLM 返回的 plan JSON。失败时尝试从 markdown 提取，否则返回 fallback。"""
    from backend.core.metrics import AGENT_PLAN_GENERATION_TOTAL
    # 直接解析
    try:
        plan = json.loads(content)
        if isinstance(plan, dict) and "steps" in plan:
            return plan
    except json.JSONDecodeError:
        pass

    # 从 markdown ```json ... ``` 提取
    if "```json" in content:
        try:
            inner = content.split("```json", 1)[1].split("```", 1)[0]
            plan = json.loads(inner)
            if isinstance(plan, dict):
                return plan
        except Exception:
            pass

    logger.warning(f"[Plan] JSON 解析失败: {content[:200]}")
    AGENT_PLAN_GENERATION_TOTAL.labels(status="parse_error").inc()
    return {
        "goal": "直接回答",
        "steps": [],
        "mode": "immediate",
        "constraints": {},
    }
```

## 四、维度 1: 约束提取前置

**设计**：与 PLAN_PROMPT 合并到同一次 LLM 请求。Prompt 要求输出 `constraints` + `steps` 两个字段。0 次额外 Token。

**注入方式**：主循环在执行每一步工具调用时，将约束合并到参数中：

```python
TOOL_CONSTRAINT_MAP = {
    "search_posts": ["preferred_platforms"],
    "filter_content": ["exclude", "language"],
    "generate_itinerary": ["budget_max", "accessibility", "duration", "exclude"],
    "extract_slots": ["exclude"],
}


def _inject_constraints(params: dict, constraints: dict, tool_name: str) -> dict:
    """将约束注入工具参数。只注入工具接受的字段，不覆盖用户显式指定的值。"""
    allowed = TOOL_CONSTRAINT_MAP.get(tool_name, [])
    for key in allowed:
        if key in constraints and key not in params:
            params[key] = constraints[key]
    return params
```

## 五、维度 2: 计划模板复用（★ R-005 修订版）

```python
def _match_workflow_template_sync(user_msg: str, owner_id: str) -> Optional[dict]:
    """Jaccard 相似度匹配（同步版，运行在线程池中）。"""
    import jieba
    from backend.services.agent_service.workflows_db import WorkflowsDB

    db = WorkflowsDB()
    # ★ R-005 修订：enabled=1 过滤是关键，auto_template 累积时强制 enabled=1
    candidates = db.query(
        "SELECT * FROM workflows WHERE source IN ('preset','auto_template') AND enabled=1"
    )
    user_keywords = set(jieba.cut(user_msg))
    if not user_keywords:
        return None
    best_score, best_template = 0.0, None
    for t in candidates:
        pattern_text = (t.get("name") or "") + " " + (t.get("description") or "")
        pattern_keywords = set(jieba.cut(pattern_text))
        if not pattern_keywords:
            continue
        score = len(user_keywords & pattern_keywords) / max(len(user_keywords | pattern_keywords), 1)
        if score > best_score:
            best_score = score
            best_template = t
    return best_template if best_score > 0.6 else None


async def _match_workflow_template(user_msg: str, owner_id: str) -> Optional[dict]:
    """异步包装：模板匹配放线程池，不阻塞事件循环，可被 cancel。"""
    loop = asyncio.get_running_loop()
    return await loop.run_in_executor(
        None, _match_workflow_template_sync, user_msg, owner_id
    )


def _instantiate_template(template: dict, user_msg: str) -> dict:
    """将 workflow 条目实例化为具体 plan。"""
    steps = json.loads(template["steps_json"])
    constraints = json.loads(template.get("constraints_template") or "{}")
    # 提取 user_msg 中的实体（占位符 {{keyword}} 等替换为具体值）
    entities = _extract_entities(user_msg)
    for step in steps:
        for key, val in list(step.get("params", {}).items()):
            if isinstance(val, str) and val.startswith("{{") and val.endswith("}}"):
                ref = val[2:-2].strip()
                # 跳过 step_N_result
                if ref.startswith("step_"):
                    continue
                # 普通占位符：尝试替换
                if ref in entities:
                    step["params"][key] = entities[ref]

    # ★ 命中后更新 hit_count
    try:
        from backend.services.agent_service.workflows_db import WorkflowsDB
        db = WorkflowsDB()
        with db._get_conn() as conn:
            c = conn.cursor()
            c.execute("""
                UPDATE workflows
                SET hit_count = hit_count + 1, last_hit = ?
                WHERE id = ?
            """, [datetime.now().isoformat(), template["id"]])
            conn.commit()
    except Exception as e:
        logger.warning(f"[Plan] 更新 hit_count 失败: {e}")

    return {
        "goal": f"复用模板: {template['name']}",
        "mode": "immediate",
        "constraints": constraints,
        "steps": steps,
        "from_template": True,
        "template_id": template["id"],
    }


def _extract_entities(user_msg: str) -> dict:
    """从用户输入中提取实体（简单实现：jieba 切词后取名词）。"""
    import jieba.posseg as pseg
    entities = {}
    for word, flag in pseg.cut(user_msg):
        if flag.startswith("n") and len(word) >= 2:
            # 第一个名词作为 keyword
            if "keyword" not in entities:
                entities["keyword"] = word
            entities[word] = word
    return entities
```

### 5.1 auto_template 累积（★ R-005 修订版：UPSERT 强制 enabled=1）

```python
async def _maybe_save_template(ctx: AgentContext):
    """如果 Agent 自主完成所有步骤，UPSERT auto_template。

    ★ 弱点1 补强：必须所有 critical 步骤都成功才累积。
       防止"局部失败但被当作成功模板"的下次命中。
    """
    if not (ctx.plan and ctx.plan.get("steps")):
        return
    if ctx.plan.get("from_template"):
        return  # 模板命中不重复保存
    if ctx.user_intervened:
        return  # 用户中途干预，不保存为模板
    if ctx.plan.get("mode") == "scheduled":
        return  # 调度型直接走 P4，不进 auto_template

    # ★ 弱点1：校验所有 critical 步骤是否成功
    step_results = ctx.plan.get("step_results", {})
    critical_failed = []
    for step in ctx.plan["steps"]:
        if step.get("criticality") != "critical":
            continue
        sid = step.get("step")
        sr = step_results.get(f"step_{sid}") or step_results.get(sid) or {}
        # sr 可能是 dict（含 success）或 JSON 字符串
        if isinstance(sr, str):
            try:
                sr = json.loads(sr)
            except Exception:
                sr = {}
        success = sr.get("success", True) if isinstance(sr, dict) else True
        skipped = sr.get("skipped", False) if isinstance(sr, dict) else False
        if not success or skipped:
            critical_failed.append(sid)

    if critical_failed:
        logger.info(
            f"[Plan] 跳过 auto_template 累积：critical 步骤失败 {critical_failed}"
        )
        return

    try:
        from backend.services.agent_service.workflows_db import WorkflowsDB
        db = WorkflowsDB()
        name = _parameterize_user_message(ctx) or ctx.plan.get("goal", "auto_template")
        constraints = json.dumps(ctx.plan.get("constraints", {}), ensure_ascii=False)
        steps_json = json.dumps(ctx.plan["steps"], ensure_ascii=False)
        wf_id = db.upsert_auto_template(
            owner_id=ctx.owner_id,
            name=name[:200],
            steps_json=steps_json,
            constraints_template=constraints,
        )
        logger.info(f"[Plan] auto_template 累积: id={wf_id}, name={name}")
    except Exception as e:
        logger.warning(f"[Plan] 保存 auto_template 失败: {e}")


def _parameterize_user_message(ctx: AgentContext) -> str:
    """把用户具体输入抽象为模板名（用 {品牌}/{关键词} 占位符替换）。

    简单实现：取第一个名词作为占位符。
    """
    user_msg = _get_last_user_message(ctx)
    entities = _extract_entities(user_msg)
    kw = entities.get("keyword", "")
    if not kw:
        return ""
    # 把具体关键词替换为占位符
    return user_msg.replace(kw, "{" + kw + "}") if kw else user_msg
```

## 六、维度 3: 关键路径标注

PLAN_PROMPT 要求 LLM 为每个 step 标注 `criticality`：

**三级处置策略**：

| criticality | 失败时行为 | 重试次数 | 降级策略 |
|------------|----------|---------|---------|
| `critical` | 终止执行，向用户报告根因 | 1 次 | 无，直接终止 |
| `required` | 重试后降级 | 2 次 | 降级为 optional（静默跳过） |
| `optional` | 静默跳过，不阻塞后续步骤 | 0 次 | — |

执行时由 `execute_workflow_steps`（P1）统一处理；主循环路径不重复实现。

```python
def _detect_anomaly(result) -> Optional[str]:
    """检测步骤结果是否异常。result 可能是 dict 或 JSON 字符串。"""
    if isinstance(result, str):
        try:
            result = json.loads(result)
        except Exception:
            return None

    if not isinstance(result, dict):
        return None

    # 错误字段
    if result.get("error"):
        return f"工具返回错误: {str(result['error'])[:100]}"

    # ★ R-006 修订：嵌套 data 兜底（兼容 {"data": {"posts": [...]}} 格式）
    data = (
        result.get("posts")
        or result.get("results")
        or (result.get("data") or {}).get("posts")
        or (result.get("data") or {}).get("results")
    )
    if isinstance(data, list) and len(data) == 0:
        return "返回空数据，可能是过滤条件过严或数据源无匹配"
    return None


async def _maybe_adjust_plan(step_result, step_idx: int, ctx: AgentContext) -> Optional[str]:
    """检查步骤结果，必要时触发计划修正。

    ★ R-006 修订：返回 emit_plan_adjusted 字符串或 None，**不是 generator**。
    调用方写法：chunk = await _maybe_adjust_plan(...); if chunk: yield chunk
    """
    anomaly = _detect_anomaly(step_result)
    if not anomaly:
        return None
    if ctx.plan.get("adjustment_count", 0) >= 2:
        logger.warning(f"[Plan] 已达最大调整次数 (2)，不再修正")
        return None

    adjust_prompt = PLAN_ADJUST_PROMPT.format(
        original_plan=json.dumps(ctx.plan, ensure_ascii=False, default=str),
        failed_step=step_idx + 1,  # 1-based
        failed_result=json.dumps(step_result, ensure_ascii=False, default=str)[:500],
        anomaly_reason=anomaly,
        remaining_steps=json.dumps(ctx.plan["steps"][step_idx:], ensure_ascii=False, default=str),
    )

    try:
        # 放到线程池 + 可被 cancel
        loop = asyncio.get_running_loop()
        adjusted = await loop.run_in_executor(
            None, _call_plan_adjust_llm_sync,
            adjust_prompt, ctx.owner_id,
        )
        new_steps_data = json.loads(adjusted)
        ctx.plan["steps"] = ctx.plan["steps"][:step_idx] + new_steps_data["adjusted_steps"]
        ctx.plan["adjustment_note"] = new_steps_data.get("note", "")
        ctx.plan["adjustment_count"] = ctx.plan.get("adjustment_count", 0) + 1
        return emit_plan_adjusted(ctx.plan)
    except asyncio.CancelledError:
        raise
    except Exception as e:
        logger.warning(f"[Plan] 计划修正失败: {e}")
        return None


def _call_plan_adjust_llm_sync(prompt: str, owner_id: str) -> str:
    key, url, model = _get_agent_config_for(owner_id)
    client = OpenAI(api_key=key, base_url=url)
    resp = client.chat.completions.create(
        model=model or settings.DEFAULT_MODEL,
        messages=[{"role": "user", "content": prompt}],
        temperature=0.1,
        max_tokens=200,
    )
    return resp.choices[0].message.content.strip()
```

## 八、PLAN_PROMPT（合并约束 + 关键路径）

```python
PLAN_PROMPT = """你是一个任务规划专家。先分析用户意图和约束条件，再拆解执行步骤。

当前可用的核心工具：
{tools}

用户问题：{user_message}

请输出 JSON（不要其他内容）：
{{
  "goal": "一句话描述最终目标",
  "mode": "immediate",
  "constraints": {{
    "budget_max": "预算上限(数字，无则为null)",
    "accessibility": "elderly_friendly|wheelchair|normal",
    "exclude": ["排除项列表"],
    "duration": "时间跨度(如'3天')",
    "preferred_platforms": ["优先平台列表"],
    "language": "zh|en"
  }},
  "steps": [
    {{
      "step": 1,
      "description": "这一步要做什么",
      "tool": "工具名",
      "criticality": "critical|required|optional",
      "why": "为什么需要这一步"
    }}
  ]
}}

规则：
- 简单问题（直接回答即可）→ steps 为空数组，constraints 全部为 null/空
- 复杂问题 → 拆为 2-5 步
- 如果用户提到"定时""定期""每天早上"等，mode 改为 "scheduled"，增加 "schedule" 字段：
  {{"cron": "cron表达式", "description": "触发时机描述"}}
- criticality 标注原则：
  critical = 数据采集步骤（后面步骤依赖其结果），失败时直接终止
  required = 核心分析步骤，失败时重试 2 次后降级跳过
  optional = 推送/格式化步骤，失败不影响主流程
- 约束提取：从用户输入中抽取限制条件，无则填 null/空数组
- 只输出 JSON，不要解释"""
```

def emit_plan(plan: dict) -> str:
    """通知前端 Agent 的规划结果"""
    return emit("plan", {
        "goal": plan.get("goal", ""),
        "steps": plan.get("steps", []),
        "mode": plan.get("mode", "immediate"),
        "constraints": plan.get("constraints", {}),
        "from_template": plan.get("from_template", False),
    })


def emit_plan_adjusted(plan: dict) -> str:
    """通知前端计划已动态调整"""
    return emit("plan_adjusted", {
        "note": plan.get("adjustment_note", ""),
        "steps": plan.get("steps", []),
        "adjustment_count": plan.get("adjustment_count", 0),
    })


def emit_done_with_message(message: str) -> str:
    """phase_plan 完成且 mode=scheduled 时使用，带文本说明"""
    return emit("done_with_message", {"message": message})
```

## 十二、P4 _persist_workflow（mode=scheduled 持久化）

```python
async def _persist_workflow(ctx: AgentContext) -> Optional[int]:
    """phase_plan 输出 mode=scheduled 时落库。

    返回 workflow_id。落库失败返回 None（不阻断当前对话）。

    ★ 弱点2 补强：cron 表达式用 croniter 校验合法性。
       非法 cron → 仍保存但 enabled=0，前端可见但不可用。
       防止 LLM 输出错误 cron（如 "0 9 everyday"）导致任务永远不触发。
    """
    if not (ctx.plan and ctx.plan.get("mode") == "scheduled"):
        return None

    schedule = ctx.plan.get("schedule") or {}
    cron = schedule.get("cron", "")
    desc = schedule.get("description", "")
    if not cron:
        logger.warning(f"[Plan] mode=scheduled 但缺 cron 字段，跳过持久化")
        return None

    # ★ 弱点2：cron 合法性校验
    cron_valid = True
    cron_error = ""
    try:
        from croniter import croniter
        croniter(cron)  # 解析失败抛 CroniterBadCronError
    except ImportError:
        # croniter 未安装：降级用正则粗校验（5 段或 6 段）
        import re
        if not re.match(r"^[\d*/,\-\s]+$", cron):
            cron_valid = False
            cron_error = "cron 含非数字字符且 croniter 库未安装"
        else:
            parts = cron.split()
            if len(parts) not in (5, 6):
                cron_valid = False
                cron_error = f"cron 段数 {len(parts)} 不在 5/6 范围内"
    except Exception as e:
        cron_valid = False
        cron_error = str(e)

    try:
        from backend.services.agent_service.workflows_db import WorkflowsDB
        db = WorkflowsDB()
        # 即使 cron 非法也保存，方便用户手动修正
        wf_id = db.insert_workflow(
            owner_id=ctx.owner_id,
            name=ctx.plan.get("goal", "未命名工作流")[:200],
            steps_json=json.dumps(ctx.plan.get("steps", []), ensure_ascii=False),
            constraints_template=json.dumps(ctx.plan.get("constraints", {}), ensure_ascii=False),
            source="user",
            schedule_cron=cron,
            schedule_desc=desc,
            is_composite_tool=0,
            enabled=1 if cron_valid else 0,  # 非法 cron 默认停用
        )
        ctx.workflow_id = wf_id
        ctx.cron_valid = cron_valid  # 用于 emit_done_with_message 提示
        ctx.cron_error = cron_error
        return wf_id
    except Exception as e:
        logger.error(f"[Plan] 持久化 scheduled 工作流失败: {e}")
        return None
```

## 十五、验收标准

**基础规划：**
- [ ] 用户发送"对比理想和蔚来过去一周的售后服务讨论" → plan 含 3-5 个 steps
- [ ] 用户发送"你好" → plan.steps 为空数组
- [ ] 用户发送"每天早上 9 点扫描理想汽车负面" → plan.mode == "scheduled"，含 schedule 字段
- [ ] LLM 返回非 JSON → 回退到无计划模式（AGENT_PLAN_GENERATION_TOTAL.labels(status="parse_error") +1）
- [ ] 用户传 `skip_plan=true` → 跳过整个 phase_plan，直接进入主循环

**约束提取：**
- [ ] 用户说"预算 3000 以内，带老人，不要爬山，去长沙3天" → plan.constraints 含 `budget_max:3000, accessibility:elderly_friendly, exclude:["爬山"], duration:"3天"`
- [ ] 约束正确注入到 `generate_itinerary` 工具参数中
- [ ] 用户未提及约束 → constraints 字段全为 null/空，不影响执行

**模板复用（R-005 修订）：**
- [ ] 第 1 次"看看华为负面" → LLM 规划，执行完成后 UPSERT INTO workflows (source='auto_template', enabled=1, hit_count=1)
- [ ] 第 2 次"看看理想负面" → LLM 规划，完成后 UPSERT (hit_count=2)
- [ ] 第 3 次"看看比亚迪负面" → 模板命中（Jaccard > 0.6），0 次 LLM 调用
- [ ] "深度分析华为负面" → 命中 preset `deep_analyze_topic`
- [ ] 模板匹配 Jaccard 阈值 0.6 生效——完全不相关的请求不命中
- [ ] auto_template 累积**强制 enabled=1**
- [ ] 模板匹配在 `asyncio.to_thread` 中执行，可被 cancel_event 中断

**关键路径：**
- [ ] critical 步骤失败 → 执行终止，AGENT_PLAN_GENERATION_TOTAL 计数 +1（status=failed 经由 execute_workflow_steps）
- [ ] required 步骤失败 → 重试 2 次后降级跳过，输出含 `skipped:true`
- [ ] optional 步骤失败 → 静默跳过

**动态调整（R-006 修订）：**
- [ ] `filter_content` 返回 0 条 → 触发 `_maybe_adjust_plan`（嵌套 data 兜底生效）
- [ ] 修正返回 string，主循环 `chunk = await _maybe_adjust_plan(...); if chunk: yield chunk`
- [ ] 调整达到 2 次上限 → 不再触发修正
- [ ] 正常结果不触发修正（0 次额外 Token）

**取消：**
- [ ] 前端在模板匹配阶段断开 → CancelRegistry 生效
- [ ] 前端在 LLM 规划阶段断开 → CancelRegistry 生效
- [ ] 前端在计划修正阶段断开 → CancelRegistry 生效

**P4 scheduled 工作流（R-007/R-010 修订）：**
- [ ] mode=scheduled 时调用 `_persist_workflow` → workflows 表新增 source='user' 行
- [ ] 持久化后 emit `done_with_message` 事件，前端可看到"已创建定时任务"
- [ ] 持久化后**不**自动执行（避免试探性问题创建后立即跑）

**AgentContext 字段（R-007）：**
- [ ] `adjustment_count` 字段初值 0，P3 调用 `ctx.plan.get("adjustment_count", 0)` 不再总是默认值
- [ ] `user_intervened` 默认 False，可由用户追加消息时置 True 阻止 auto_template 累积

**弱点 1 补强（auto_template 累积校验）：**
- [ ] critical 步骤失败时跳过累积（`step_results[critical_step].success == False` 时不调用 upsert_auto_template）
- [ ] ctx.plan["step_results"] 必须在 phase_act 后正确写入每步 success/skipped 字段
- [ ] **推荐**：P3 主循环或 execute_workflow_steps 完成后，把每个步骤的成功状态回填到 ctx.plan["step_results"][f"step_{N}"] = {success: True/False, skipped: True/False}

**弱点 2 补强（cron 表达式校验）：**
- [ ] 安装 croniter 依赖（`pip install croniter`）
- [ ] 非法 cron 表达式 → 工作流 enabled=0 + emit_done_with_message 包含错误详情
- [ ] 合法 cron → 工作流 enabled=1，正常调度
- [ ] croniter 库未安装时降级为正则粗校验（5/6 段数字）
- [ ] 用户能用 manage_workflow 修正 cron 后手动 enable
