# 打断机制设计

> 目标：覆盖三种场景的可靠打断——Agent 对话、Pipeline 分析、爬虫采集。确保打断后状态一致、资源释放干净、再次可用。
> 原则：不引入新中间件，只用 asyncio 原生能力 + 信号量检查。

**实施状态：已完成（2026-06-16）。**

| 文件 | 状态 | 说明 |
|------|------|------|
| `agent_core.py` | ✅ | 主循环 GeneratorExit 捕获 + CancelRegistry + 3 层取消点 |
| `sse.py` | ✅ | emit_cancelled 事件 |
| `api.py` (agent) | ✅ | POST /api/agent/chat/{session_id}/cancel 端点 |
| `pipeline.py` | ✅ | PipelineCanceller 类 + check() 检查点 + CancelledError 处理 |
| `crawler_manager.py` | ✅ | pause() / resume() / cancel() + 跨进程信号文件 |
| `crawler.py` (路由) | ✅ | POST `/{platform}/pause` / `resume` / `cancel` 端点 |
| `tools/scan.py` | ✅ | pause_scan / resume_scan Agent 工具 |

## 一、现状

| 场景 | 当前能力 | 断在哪里 |
|------|---------|---------|
| Agent SSE 流式对话 | 前端已有 `AbortController`，断的是 fetch 但后端 async generator 跑完才停 | 后端检测不到客户端断开 |
| Pipeline 分析 | `asyncio.wait_for` 整体超时，无逐任务打断 | 集群分析阶段只能整个等超时 |
| 爬虫采集 | `CrawlerManager.stop()` 终止进程，但无逐平台中途退出 | `_read_output` 阻塞在读 stdout 上 |

## 二、Agent SSE 打断

### 2.1 问题

当前 `chat_with_agent_stream()` 是一个 async generator，前端断开 fetch 后后端仍在 `async for chunk in stream` 中循环。原因：`StreamingResponse` 检测到客户端断开时会停止消费 generator，但 generator 本身没有 `try/finally` 来取消内部的 LLM stream。

### 2.2 方案：后端检测 + 主动取消

```
前端                         后端                          OpenAI API
 │                          │                          │
 ├── POST /api/agent/chat ──┤                          │
 │                          ├── AsyncOpenAI.stream() ──┤
 │                          │  async for chunk          │
 │   (fetch 断开)           │    │  ← 检测到 generator   │
 │   AbortController        │    │    被丢弃             │
 │   cancel()               │    ├── stream.close() ────┤  API 立即停
 │                          │    ├── 取消 phase_act      │
 │                          │    ├── 保持 current_messages│
 │                          │    └── emit_done()         │
```

### 2.3 实现

**`agent_core.py`**：在 `chat_with_agent_stream` 中捕获 `asyncio.CancelledError` 或 `GeneratorExit`，确保所有路径都走 `phase_finish`：

```python
async def chat_with_agent_stream(messages, session_id=None, _request=None):
    # ... 初始化 ...
    yield emit_session(ctx.session_id)

    try:
        for i in range(ctx.max_iterations):
            ctx.iteration = i

            try:
                stream = await client.chat.completions.create(
                    ..., stream=True,
                )

                async for chunk in stream:
                    try:
                        yield emit_text(delta.content)  # yield 可能抛异常
                    except GeneratorExit:
                        # ── 前端断开时的关键处理 ──
                        logger.info(f"[Agent] 前端断开，正在关闭 LLM stream")
                        await stream.close()  # 停止 OpenAI API 继续生成
                        raise  # 再次抛出让外层 finally 处理

                # ... 工具执行部分同理 ...

            except GeneratorExit:
                # 前端在工具执行阶段断开
                logger.info(f"[Agent] 工具执行阶段前端断开")
                raise

            except Exception as e:
                # ... 现有异常处理 ...
                pass

    except GeneratorExit:
        # 统一打断处理：保留已有上下文，标记 done
        logger.info(f"[Agent] 会话 {ctx.session_id} 被用户打断")
        yield emit_done()
        # 异步写记忆（已有上下文不丢）
        asyncio.create_task(_write_memory_async(
            ctx.session_id, ctx.messages, ctx.owner_id, ctx.text_collector
        ))
        return
    except Exception as e:
        # ... 现有兜底 ...
```

**`agent_core.py` phase_act**：如果工具执行中的 generator 被丢弃，取消工具执行：

```python
async def phase_act(ctx, tool_call):
    # ...
    try:
        gen = tool_executor.execute(tool_name, args, ctx.current_messages,
                                     metadata={"request": ctx.request})
        while True:
            try:
                chunk = await gen.__anext__()
            except StopAsyncIteration:
                break
            try:
                yield chunk
            except GeneratorExit:
                # 工具执行中被取消 → 关闭 gen
                await gen.aclose()
                raise
    except GeneratorExit:
        logger.info(f"[Agent] 工具 {tool_name} 执行被取消")
        yield _PHASE_ACT_DONE(None)
```

### 2.4 前端改进

当前前端已在 `cancel()` 中调用 `abortRef.current?.abort()`。需额外补充：**后端感知层面**加一个显式取消端点，用于前端发出实际请求后再手动取消（非 fetch 断开场景）。

**新增 API 端点**：

```python
# api.py

class CancelRequest(BaseModel):
    session_id: str


@router.post("/api/agent/chat/{session_id}/cancel")
async def cancel_agent_stream(
    session_id: str,
    current_user: Dict = Depends(require_registered_user),
):
    """
    取消指定 session 当前正在执行的 Agent 流。
    用于前端"停止生成"按钮（区别于直接断连）。
    """
    cancelled = cancel_registry.cancel(session_id)
    return {"code": 200, "data": {"cancelled": cancelled}}
```

**取消注册表**（`agent_core.py` 新增）：

```python
# agent_core.py 文件顶部新增

_CANCEL_EVENTS: dict = {}
_CANCEL_LOCK = threading.Lock()


def _make_cancel_event(session_id: str) -> asyncio.Event:
    """为 session 注册取消事件"""
    event = asyncio.Event()
    with _CANCEL_LOCK:
        _CANCEL_EVENTS[session_id] = event
    return event


def _remove_cancel_event(session_id: str):
    with _CANCEL_LOCK:
        _CANCEL_EVENTS.pop(session_id, None)


class CancelRegistry:
    def cancel(self, session_id: str) -> bool:
        """触发取消事件。返回 True 表示有效取消。"""
        with _CANCEL_LOCK:
            event = _CANCEL_EVENTS.get(session_id)
            if event:
                event.set()
                return True
        return False

    async def wait_or_raise(self, session_id: str, step: str = ""):
        """在 Agent 主循环的关键检查点调用，被取消时抛 CancelledError。"""
        with _CANCEL_LOCK:
            event = _CANCEL_EVENTS.get(session_id)
        if event and event.is_set():
            raise asyncio.CancelledError(f"用户取消了 {step}")


cancel_registry = CancelRegistry()
```

在 main loop 关键点插入检查：

```python
await cancel_registry.wait_or_raise(ctx.session_id, "iteration_end")
```

前端调用：

```typescript
// agent/page.tsx
const handleStop = async () => {
  if (sessionId) {
    await fetch(`/api/agent/chat/${sessionId}/cancel`, { method: 'POST' });
  }
  cancel(); // 现有 AbortController
};
```

### 2.5 打断后的状态保证

| 状态 | 行为 |
|------|------|
| `current_messages` | 保留到上一轮最后工具结果为止，不丢失 |
| LLM stream | `await stream.close()`，停止 API 继续输出 |
| 正在执行的工具 | `await gen.aclose()`，不等待完成 |
| 记忆写入 | `asyncio.create_task(_write_memory_async(...))` 写入已累积的上下文 |
| 下次对话 | 用户继续发问时 `phase_build_context` 从 DB 重建上下文，感知不到打断 |

## 三、Pipeline 分析打断

### 3.1 问题

`pipeline.py` 的 `_run_inner()` 中集群分析通过 `asyncio.gather` 并行执行，此时无法单独取消某个 cluster 的分析。`asyncio.wait_for` 只能整体超时。

### 3.2 方案：轮询取消 + 逐任务 go signal

```python
class PipelineCanceller:
    """Pipeline 级别取消。每个 Pipeline 实例一个。"""

    def __init__(self):
        self._cancelled = False

    def cancel(self):
        self._cancelled = True

    @property
    def is_cancelled(self) -> bool:
        return self._cancelled

    def check(self):
        """在分析子图每轮迭代前调用。被取消时抛异常终止当前 task。"""
        if self._cancelled:
            raise asyncio.CancelledError("Pipeline 已被取消")


# RadarPipeline.__init__ 中新增
self.canceller = PipelineCanceller()

# RadarPipeline.run() 的超时逻辑改造
async def run(self, posts):
    # ...
    try:
        result = await asyncio.wait_for(
            self._run_inner(posts, background_tasks),
            timeout=self.config.timeout,
        )
        return result
    except asyncio.CancelledError:
        logger.info(f"[Pipeline] 用户取消 Pipeline")
        for t in background_tasks:
            if not t.done():
                t.cancel()
        return []  # 返回空结果，不抛异常
```

在 `_run_with_semaphore` 中插入检查点：

```python
async def _run_with_semaphore(self, cluster):
    async with self._semaphore:
        self.canceller.check()  # 每次获取信号量后检查

        # 如果使用 analyze_and_report_async（同步包装），检查点
        result = await analyze_and_report_async(...)

        self.canceller.check()  # 分析完成后、结果整理前检查

        return cluster, result, evolution_timeline
```

**对外暴露取消 API**：

```python
# pipeline.py
class PipelineCanceller:
    _instances: Dict[str, "PipelineCanceller"] = {}
    _lock = threading.Lock()

    @classmethod
    def get(cls, run_id: str) -> "PipelineCanceller":
        with cls._lock:
            if run_id not in cls._instances:
                cls._instances[run_id] = cls()
            return cls._instances[run_id]

    @classmethod
    def cancel_run(cls, run_id: str) -> bool:
        with cls._lock:
            canceller = cls._instances.get(run_id)
            if canceller:
                canceller.cancel()
                return True
        return False

    @classmethod
    def cleanup(cls, run_id: str):
        with cls._lock:
            cls._instances.pop(run_id, None)
```

结合 `_background_index` 的取消——它已经是 `asyncio.create_task`，直接用 task.cancel()：

```python
# Pipeline 结束时
for t in background_tasks:
    if not t.done():
        t.cancel()
done, pending = await asyncio.wait(background_tasks, timeout=5)
for t in pending:
    t.cancel()
    logger.info(f"[Pipeline] 后台索引任务 {t.get_name()} 超时取消")
```

### 3.3 取消链路

```
用户 / Agent / 调度器
         │
         ▼
PipelineCanceller.cancel_run(run_id)
         │
         ▼
canceller.is_cancelled = True
         │
         ├─ cluster 获取信号量时 → check() → CancelledError
         ├─ cluster 分析完成后 → check() → CancelledError
         ├─ 后台索引 task → asyncio.current_task().cancel()
         └─ pipeline.run() 的 CancelledError → return []
```

## 四、爬虫采集打断

### 4.1 问题

`CrawlerManager` 已有 `stop()` 方法（SIGTERM → kill），但这是粗暴终止。无逐平台挂起/恢复的能力，无"等当前页面爬完再停"的优雅打断。

### 4.2 方案：优雅中断 + 强制终止双模式

**`crawler_manager.py`**：新增 `pause()` + 优雅 `cancel()` + 现有 `stop()`。

```python
class CrawlerManager:
    def __init__(self):
        self.process: Optional[subprocess.Popen] = None
        self.status = "idle"
        self._pause_event = asyncio.Event()  # 初始 set（不暂停）
        self._pause_event.set()
        self._cancel_requested = False
        self._read_task: Optional[asyncio.Task] = None

    async def pause(self) -> bool:
        """暂停当前采集任务（允许当前页面完成，不启动新页面）"""
        if self.status != "running":
            return False
        self._pause_event.clear()
        self.status = "paused"
        logger.info(f"[Crawler] {self.platform} 已暂停（当前页面完成后停止）")
        return True

    async def resume(self) -> bool:
        """恢复暂停的采集任务"""
        if self.status != "paused":
            return False
        self._pause_event.set()
        self.status = "running"
        logger.info(f"[Crawler] {self.platform} 已恢复")
        return True

    async def cancel(self) -> bool:
        """
        优雅取消：标记取消请求，等待当前页面完成。
        超时 30s 后强制 SIGTERM。
        """
        if not self.process or self.process.poll() is not None:
            return False
        self._cancel_requested = True
        self.status = "cancelling"

        try:
            await asyncio.wait_for(
                self._wait_for_current_page(),
                timeout=30,
            )
        except asyncio.TimeoutError:
            logger.warning(f"[Crawler] {self.platform} 取消超时，强制终止")
            return await self.stop()

        self.status = "idle"
        return True
```

爬虫循环中插入检查点（爬虫脚本 `media_platform/*/client.py`）：


实际的跨进程通信通过文件信号量实现：

```python
# crawler_manager.py 中管理信号文件
import tempfile

class CrawlerManager:
    def __init__(self, platform: str):
        self._signal_dir = Path(tempfile.gettempdir()) / "mediaradar_crawler_signals"
        self._signal_dir.mkdir(exist_ok=True)
        self._pause_flag = self._signal_dir / f"{platform}_pause"
        self._cancel_flag = self._signal_dir / f"{platform}_cancel"

    async def pause(self):
        self._pause_flag.touch()
        self.status = "paused"

    async def resume(self):
        self._pause_flag.unlink(missing_ok=True)
        self.status = "running"

    async def cancel(self):
        self._cancel_flag.touch()
        self.status = "cancelling"

    def cleanup(self):
        """清理信号文件"""
        self._cancel_flag.unlink(missing_ok=True)
        self._pause_flag.unlink(missing_ok=True)
```

## 五、三种打断场景对比

| 维度 | Agent SSE | Pipeline 分析 | 爬虫采集 |
|------|-----------|--------------|---------|
| 触发者 | 前端用户点击"停止" | Admin 或 Agent 工具 | Admin 或 Agent 工具 |
| 机制 | `asyncio.CancelledError` + `GeneratorExit` | `PipelineCanceller` 轮询检查 | 文件信号量 |
| 优雅程度 | 立即停 | 当前 cluster 完成后停 | 当前页面完成后停 |
| 超时兜底 | 无需（async gen 同步停） | `asyncio.wait_for` 整体超时 | 30s → SIGTERM → 3s → kill |
| 恢复 | 从 DB 重建上下文 | 下次调度重跑 | Healer 自动重启 |
| 前端API | `POST /.../cancel` + `AbortController` | `POST /api/scan/cancel` | `POST /crawler/{platform}/cancel` |
